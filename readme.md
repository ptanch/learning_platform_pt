# LMS API — Django REST Framework учебный проект

Этот проект создан в рамках изучения Django REST Framework (DRF).
Цель — разработать backend-часть LMS-системы, в которой пользователи могут размещать свои обучающие материалы: курсы и уроки.

Проект представляет собой REST API, возвращающий клиенту JSON-структуры, и используется как серверная часть для SPA-приложения.

## 📌 Функциональность проекта

На текущем этапе реализованы:

🔹 1. Подключение DRF

Создан новый Django-проект.
DRF подключён в settings.py через INSTALLED_APPS.

🔹 2. Модели

Созданы три основные сущности:
1. `User`
Модель размещена в приложении `users`.
Используется для хранения информации о пользователях системы.
2. `Course`
Размещена в приложении `lms`.
Отражает учебный курс.
Может содержать множество уроков.
3. `Lesson`
Также размещена в `lms`.
Связан с курсом отношением «один-ко-многим».
4. `Payments`
Размещена в приложении `users`.
Отражает платежную систему приложения

🔹 3. Расширение полей сериализаторов и вычисляемые поля

Добавлены кастомные поля, которые позволяют расширять выводимые данные без изменения самой модели.
Это особенно полезно, когда необходимо предоставить пользователю дополнительную информацию, например — статистику, агрегаты или сформированные данные.

🔹 4. Вложенные сериализаторы (множественный вывод)

Была реализована возможность одновременно выводить информацию о курсе и список всех его уроков.
Это позволяет формировать сложные структуры данных в одном запросе.

🔹 5. Настройка фильтрации и сортировки для платежей

Для эндпоинта `/users/payments/` добавлена возможность:

✔️ сортировать результаты по дате оплаты
✔️ фильтровать по:

- курсу (`paid_course`)
- уроку (`paid_lesson`)
- способу оплаты (`payment_method`)

Примеры запросов:

- Отсортировать по дате `?ordering=payment_date`
- В обратном порядке `?ordering=-payment_date`
- Фильтр по курсу `?paid_course=1`
- Фильтр по уроку `?paid_lesson=4`
- Фильтр по способу `?payment_method=cash`
- Комбинированный запрос `?paid_course=1&payment_method=transfer&ordering=-payment_date`

🔹 6. Кастомная валидация данных

Для полей уроков добавлена проверка через кастомный валидатор (`validate_video_url`).
Проверяется корректность данных и соблюдение правил заполнения.

🔹 7. Постраничный вывод (`pagination`)
Списки курсов и уроков теперь выводятся постранично через кастомный класс пагинации (`CustomPagination`).
Это делает работу с большими списками более удобной и позволяет подгружать данные по частям.

🔹 8. Тестирование
Все новые функции протестированы с использованием встроенного модуля `unittest`.
Проверяются права доступа, создание и обновление объектов, корректность постраничного вывода и подписки на курсы.

### 🔐 Авторизация и права доступа

**JWT-авторизация**

В проекте реализована JWT-аутентификация с использованием `rest_framework_simplejwt`.

Добавлены следующие эндпоинты:

- POST /users/token/refresh/ — обновление access токена по refresh
- POST /users/register/ — регистрация нового пользователя

Для доступа к защищённым эндпоинтам необходимо передавать заголовок:
```
Authorization: Bearer <access_token>
```
Все эндпоинты проекта закрыты авторизацией — доступ к ресурсам возможен только после успешного входа.

### 👥 Роли и группы пользователей

Проект предусматривает разделение пользователей по ролям:

Группа "Модераторы"
Эта группа имеет расширенные права:
- могут просматривать любые курсы и уроки;
- могут редактировать любые курсы и уроки;
- не могут создавать новые объекты (Course, Lesson);
- не могут удалять объекты.

Права назначаются через Django Admin.

### 🛡 Права доступа и ограничения

В проекте настроена объектная логика доступа:

Для обычных пользователей

Пользователь может:
- просматривать только свои курсы и уроки;
- редактировать только свои курсы и уроки;
- создавать новые курсы и уроки;
- удалять только свои объекты.

Попытки обратиться к чужим данным приводят к ошибке авторизации.

Для модераторов

Модераторы могут:
- видеть и изменять все курсы и уроки независимо от владельца.

Но не могут:
- создавать новые курсы или уроки;
- удалять любые записи.

Такая логика заложена во `views.py` через кастомные разрешения (permissions), которые проверяют:

1. принадлежность пользователя к группе "модераторы";
2. совпадение владельца объекта и текущего пользователя.

## 🔧 Реализованные эндпоинты
🔹 3. CRUD для Course (через ViewSet)

Использован `ModelViewSet` для реализации всех CRUD-операций:

- GET /courses/ — список курсов
- POST /courses/ — создание курса
- GET /courses/<id>/ — получение одного курса
- PUT /courses/<id>/ — полное обновление
- PATCH /courses/<id>/ — частичное обновление
- DELETE /courses/<id>/ — удаление

🔹 4. CRUD для Lesson (через Generic Views)

Использованы generics:

- `ListCreateAPIView`
- `RetrieveUpdateAPIView`
- `DestroyAPIView`

Реализованные эндпоинты:

- GET /lessons/ — список уроков
- POST /lessons/ — создание урока
- GET /lessons/<id>/ — просмотр урока
- PUT/PATCH /lessons/<id>/ — обновление
- DELETE /lessons/<id>/ — удаление

Generics позволяют точечно подбирать только нужный функционал и дают полный контроль над логикой.

3. Обновление

## 🚀 Как запустить проект

Клонировать репозиторий:
```
git clone <your-repo-url>
cd project
```

Установить зависимости:
Если используется `Poetry`:
```
poetry install
poetry shell
```

Выполнить миграции:
```
python manage.py migrate
```

Запустить сервер:
```
python manage.py runserver
```

Теперь API доступно по адресу:
http://127.0.0.1:8000/
